# PR 생성

## 목적

현재 브랜치와 main 브랜치의 차이를 분석해서 GitHub PR 내용을 작성한다.

## 절차

1. `git branch --show-current` — 현재 브랜치명 확인
2. `git log main..HEAD --oneline` — 커밋 목록 확인 (main과 비교 불가능하면
   `git log HEAD~1..HEAD`로 대체)
3. `git diff main..HEAD` (또는 `git diff HEAD~1..HEAD`) — 전체 변경사항 확인
4. 브랜치명/커밋 메시지에서 노션 티켓 번호나 링크로 보이는 패턴을 찾아본다. 못 찾으면
   빈 칸으로 두고 채팅에서 사용자에게 티켓 링크를 물어본다 — 추측해서 채우지 않는다.

## PR 형식

```
## 개요
(변경사항 한 줄 요약)

## 변경 내용
- 변경 내용 1
- 변경 내용 2

## 관련 티켓
(노션 링크, 못 찾으면 사용자에게 확인)

## 작업 배경
(왜 이 작업이 필요했는지 — 커밋 메시지/CLAUDE.md 맥락에서 유추하고, 불명확하면 사용자에게 확인)

## 테스트 방법
- [ ] 테스트 항목 1
- [ ] 테스트 항목 2

## 스크린샷 (선택)
```

## 규칙

- 제목은 브랜치명 기반으로 한글 작성한다.
- 테스트 방법은 실제 변경 내용에 맞춰 구체적으로 쓴다 (예: "코스 상세 화면에서 위치 권한
  거부 후 재요청 시나리오 확인"). "테스트함" 같은 형식적인 문구만 넣지 않는다.
- 작성 완료 후 전체 내용을 `pbcopy` 명령으로 클립보드에 복사한다. 복사에 실패하면
  `ai/git-pr.md`에 작성한다.
