# 티켓 동기화 (sync-ticket)

## 목적

노션 'Run패스포트 마일스톤' / 'Run패스포트 Develop' 데이터베이스의 최신 상태를
로컬 `ai/develop-ticket.md`에 동기화한다.

## 대상 범위

'Run패스포트 Develop' DB에서 **담당 영역(정확한 속성명은 실행 시점에 확인) = '프론트엔드'**인
페이지만 대상으로 한다.

## 절차

### 1. 스키마부터 확인한다 — 속성명을 추측하지 않는다

- `mcp__notion__notion-search`로 'Run패스포트 마일스톤', 'Run패스포트 Develop' 데이터소스를
  찾는다.
- `mcp__notion__notion-query-data-sources`(또는 `mcp__notion__notion-fetch`)로
  'Run패스포트 Develop'의 실제 속성 스키마를 조회해서, "담당 영역"에 해당하는 속성명과
  '프론트엔드'에 해당하는 select 옵션의 정확한 표기를 확인한다.
- 스키마나 옵션값이 예상('담당영역', '프론트엔드')과 다르면 **추측해서 진행하지 말고
  실제 값을 채팅에 보여준 뒤 그 값 기준으로 진행한다.**

### 2. 마일스톤 파악

- 'Run패스포트 마일스톤' DB를 조회해서 전체 마일스톤 목록과 기간을 파악한다.

### 3. 프론트엔드 티켓 조회

- 'Run패스포트 Develop' DB에서 담당 영역이 '프론트엔드'(1단계에서 확인한 정확한 값)인
  페이지만 필터링한다.
- 각 페이지를 `mcp__notion__notion-fetch`로 열어 본문(작업 내용, 완료 조건, 선행 티켓)을
  읽는다.

### 4. 로컬 문서로 전개

노션 티켓 1개가 실제 개발 단위로는 여러 개로 쪼개질 수 있다. 노션은 상위 단위, 로컬은
실행 단위로 보고 **노션 티켓 1개당 보통 2~3개의 세부 개발 항목**으로 전개해서 작성한다.

`ai/develop-ticket.md`의 "티켓 목록" 아래에 아래 형식으로 반영한다:

```
## [마일스톤명] 티켓명

- 노션 링크: (URL)
- 상태: 시작전 / 진행중 / 완료
- 세부 개발 항목:
  - [ ] 세부 항목 1 (구체적 실행 단위)
  - [ ] 세부 항목 2
  - [ ] 세부 항목 3
- 완료 조건: (노션 본문에서 가져옴)
- 선행 티켓: (있으면)
```

### 5. 병합 규칙

- 로컬에 이미 있는 항목인데 노션 내용이 바뀌었으면 → 내용만 갱신하고, 로컬에서 이미
  표시된 진행 상태(진행중/완료 체크)는 그대로 유지한다.
- 노션에서 삭제된 티켓 → **자동 삭제하지 않는다.** 목록으로 정리해서 사용자에게 삭제
  여부를 물어본다.
- 노션에는 없고 로컬에만 있는 항목 → 건드리지 않는다 (로컬 우선순위 존중).
- `develop-ticket.md`의 "진행 규칙" 섹션(CLAUDE.md 요약)은 건드리지 않는다.

## 완료 후 보고

- 신규 추가된 항목 수
- 갱신된 항목 수
- 노션-로컬 불일치로 사용자 확인이 필요한 항목 목록 (삭제된 티켓, 스키마/옵션값이
  예상과 달랐던 경우 등)

## 금지사항

- 노션 원본 페이지/DB는 읽기 전용으로만 다룬다 (내용 수정, 속성/옵션 추가 금지).
- 로컬에서 자동으로 항목을 삭제하지 않는다 — 항상 사용자 확인을 받는다.
- `develop-ticket.md`의 기존 진행 상태를 임의로 되돌리지 않는다.
